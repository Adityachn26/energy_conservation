# API

Run: `uvicorn api.main:app --reload` · Interactive docs: <http://localhost:8000/docs> · Code: `api/`

All timestamps are local meter time (timezone in `GET /settings`). Validation errors return **422** with
details; unknown meters **404**; missing model **503**; unexpected errors **500** with a generic message
(details only in server logs).

| Method | Path | Query / body | Returns |
|---|---|---|---|
| GET | `/health` | — | status, DB check, loaded model, data source, `is_synthetic` |
| GET | `/meters` | — | meters with record counts and first/last timestamps |
| GET | `/consumption` | `meter_code?`, `start?`, `end?`, `granularity=hourly\|daily\|weekly\|monthly` | consumption series (all meters summed if no meter) |
| GET | `/consumption/by-meter` | `start?`, `end?` | total & average kWh per meter |
| GET | `/overview` | `meter_code?`, `start?`, `end?` | KPIs: total, average, highest hour, peak count, **estimated** cost |
| POST | `/predict` | `{"meter_code": "...", "horizon_hours": 1-24, "store": true}` | forecast, peak flags, estimated cost, recommendations, notes |
| GET | `/predictions` | `meter_code`, `start?`, `end?`, `prediction_type=backtest\|live`, `limit` | stored predictions joined with actuals and error |
| GET | `/peaks` | `meter_code?`, `start?`, `end?`, `order_by=timestamp\|kwh`, `limit` | peak events |
| GET | `/peaks/summary` | `meter_code?`, `start?`, `end?` | thresholds, frequency, by hour/weekday, top dates |
| GET | `/recommendations` | `meter_code?`, `limit` | latest distinct recommendations |
| GET | `/model-performance` | — | comparison of all models from the latest training run, split, feature importance |
| GET | `/settings` | — | tariff, peak percentile, timezone, currency |
| PUT | `/settings` | `{"tariff_per_kwh": 0-1000, "peak_percentile": 50-<100, "timezone": IANA, "currency": "INR"}` | updated settings (peak events recomputed if the percentile changed) |

## Prediction workflow (`POST /predict`)

```
meter history (DB) → features (same code as training) → saved model → forecast
→ peak check (meter's P-th percentile) → estimated cost (tariff) → rule-based recommendations
→ store predictions + recommendations (if store=true) → JSON response
```

"Next hour" means the hour after the meter's latest stored reading (the dataset is historical).

Example:

```bash
curl -X POST localhost:8000/predict -H 'content-type: application/json' \
     -d '{"meter_code": "SYN_01", "horizon_hours": 6, "store": false}'
```

## Security notes

- No credentials in code; DB URL built from environment variables; logs hide the password.
- All inputs validated by Pydantic (ranges, IANA timezone, 3-letter currency, horizon 1–24).
- SQL is generated by SQLAlchemy with bound parameters (no string-built SQL).
- Not yet implemented: authentication on `PUT /settings` (listed in future scope).
